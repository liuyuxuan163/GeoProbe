## 阶段 0：先搞清"这个实验到底在问什么"（5 分钟）

### 一句话

> **大语言模型内部，到底有没有"记住"地理位置？**

这个问题不能用"问它"来回答 —— 因为模型输出的文本可能是背模板、可能是猜。
所以要**绕过输出，直接看内部表征**。

### 用一个类比理解"探针"

想象你怀疑一个人的脑子里有一张地图，但你不能问他（他可能说谎或说不知道）。
你能做的只有一件事：**在他想到某个地名时，偷偷读一下他的脑电波**。

然后：

1. 找 108 个地名（Paris、Tokyo、Brazil…），记下它们的真实经纬度
2. 读每个地名对应的"脑电波"（隐层向量）
3. 训练一个**极简的线性模型**：脑电波 → 经纬度
4. 如果这个简单模型能推得挺准 → 说明经纬度信息**明确地摆在脑电波里**（线性可解码）

**这就是 probing（探针）**。它的全部意义是回答一个问题：

> **"知道"和"说得出"是两件事。模型可能表征里有信息，但输出时说不知道；也可能输出对了但只是背了模板。**

### 三个必须分清的概念

| 概念 | 是什么 | 本项目里 |
|---|---|---|
| **表征（representation）** | 模型的内部向量 | 隐层激活，896 维 |
| **探针（probe）** | 从表征预测某个属性的简单模型 | Ridge 线性回归 |
| **输出（output）** | 模型生成的文本 | **本项目完全不看它** |

### 三组词：为什么必须是三组

```
A 组 control   108 个无歧义地名    → 探针只在这里训练
B 组 ambiguous  27 个歧义地名      → 用 A 组训练好的探针来测
C 组 nongeo     24 个非地名        → 负对照
```

**关键设计**：探针**只在 A 组上训练**，从没在 B 组上训练过。

所以 B 组的输出反映的是**模型自己**对那个词的理解，没有被训练过程引导。
**这就是"探针"和"分类器"的本质区别。**

### 为什么 B 组要带"备选坐标"

`Georgia` 的真值填的是**国家格鲁吉亚**（42.3, 43.4），
但还额外记了**美国佐治亚州**（32.2, -82.9）当备选。

于是能回答一个比"误差多大"更有意思的问题：

### ② 编码目标：`geoprobe/targets.py`（10 分钟）

**全文只有 107 行，值得全读。**

核心是这一件事：

```
latlon 模式：y = [lat, lon]               ← 线性
sincos 模式：y = [lat, sin λ, cos λ]      ← 经度放到单位圆上
```

**为什么需要 sincos？** 因为经度是**循环量**：

```
经度 179° 与 -179° 地理上只差 2°（相邻）
但在线性目标空间里相差 358°
```

线性回归无法表达这种周期性，所以跨日界线的地名必然误差爆炸。

**这个坑不是想象出来的，而是实测的**（在合成数据上）：

| 编码 | 全部点经度误差 | 跨日界线点（\|lon\|>155°） |
|---|---|---|
| latlon | 38.3° | **127.7°** |
| sincos | **0.2°** | **0.2°** |

> **思考题**：`decode` 时为什么用 `atan2(sin, cos)` 而不是 `arcsin(sin)`？
>
> 因为 `arcsin` 只能还原 [-90°, 90°]，会丢失象限信息；`atan2` 能还原完整 360°。

### ③ 训练探针：`geoprobe/probe.py`（10 分钟）

**读三个类**：`RidgeProbe`（L59）、`MLPProbe`（L97）、`MeanProbe`（L141）。

核心只有一句：

```python
RidgeCV(alphas=..., cv=folds).fit(X, Y)
```

**三个要理解的点**：

| 点 | 为什么 |
|---|---|
| 用 **Ridge** 而不是普通最小二乘 | 隐层 896 维 > 样本 86 个，OLS 会过拟合甚至无解；L2 正则让解唯一 |
| alpha 用**训练集内部 CV** 选 | 如果用测试集选 alpha，就是数据泄露，指标虚高 |
| 用**线性**而不是神经网络 | 线性可解码 = 信息"摆在那里"；必须用深层网络才能解码 = 信息是隐式的 |

**`MLPProbe` 的作用**：对照。如果 Ridge 差但 MLP 好，说明信息存在但非线性编码。

### ④ 评估：`geoprobe/metrics.py`（12 分钟）

**这是全项目最需要理解"为什么"的模块。**

读这四个：

| 位置 | 内容 |
|---|---|
| L45 `haversine_km` | 球面大圆距离 |
| L187 `evaluate_predictions` | 汇总所有指标 |
| L238 `circular_r2` | 经度专用 R² |
| L97 `bootstrap_ci` | 置信区间 |

#### 为什么主指标是 **Haversine 公里**，不是 R²

三个理由：

1. **R² 对经纬度两维取平均**会把结构糊掉（sklearn 默认 `uniform_average`）
2. **MSE 的单位是"度的平方"**，没有物理意义 —— 12.5 平方度是好是差？
3. **经纬度是球面坐标**，同一个"度"误差在赤道和北纬 60° 相差一倍

> `R² = 0.85` 听起来不错，但平均误差可能是 3,000 公里。
> **公里数有物理意义，R² 没有。**

#### 为什么经度不能用普通 R²

```
真实 -179°、预测 +179°（地理上只差 2°）
  → 线性残差 358° → R² 崩到 -3.0
  → 圆形 R²（最短角距离）→ 给出合理值
```

**`circular_r2` 做两件事**：用最短角距离替代线性差值；用**圆形均值**当零模型。

#### 为什么用 bootstrap 而不是"均值 ± 标准误"

公里误差是**长尾分布**（少数地点错得极远），均值不稳健。
中位数更合适，但中位数的解析置信区间不好算 —— bootstrap 是通用解法。

### 四个基线各自排除什么

| 基线 | 做法 | 排除的解释 |
|---|---|---|
| `mean` | 永远预测训练集坐标均值 | "探针什么都没学到" |
| `random` | 随机向量 → 探针 | "随便给个数也算" |
| **`char_ngram`** | 字符 n-gram TF-IDF → 探针 | **"模型只是记住拼写规律"** |
| **`permuted`** | **打乱训练集坐标**再拟合 | **"探针在乱猜也能碰巧对"** |

### 为什么 `char_ngram` 最关键

地名和地理位置存在**拼写上的伪相关**：

- 以 `-stan` 结尾的多在中亚（Kazakhstan、Uzbekistan…）
- 以 `San` 开头的多在西语区

**纯字符特征就能捕捉这些模式。** 如果隐层不能明显优于它，
"模型编码了地理知识"这个说法就站不住 —— 只能说"模型记住了拼写"。

### 为什么 `permuted` 最严谨

把训练集的坐标随机打乱，用同样的 X 拟合，再在真实测试集上评估。

如果真实坐标的误差**远小于**打乱坐标的误差，说明探针确实读到了真信息。

> **为什么这个比"优于均值基线"强？**
> 纯噪声特征在"预测均值"基线下也可能碰巧通过
> （过拟合后个别点的预测更接近真值，把中位数拉低），
> **但过不了置换检验**。
>
> 本项目实测：无信号时 control 5,222 km vs permuted 5,318 km（几乎一样）；
> 有信号时 522 km vs 5,000 km（差 10 倍）。

1. 目标编码用了线性经度 → 探针学不好


它把"真实 -179°、预测 +179° 时线性 R² 崩到 -3"这个事实钉成了测试。

### 坑 B：R² 在小样本上极不稳定

**已修复**（改成汇总 R²）。

实测：同一层、同一编码、只换随机种子，单次 R²(经度) 的 8 个值：

```
sincos layer 5:  -0.33, 0.84, 0.82, 0.34, 0.12, 0.16, 0.21, 0.82
                 范围 [-0.33, 0.845]，跨度 1.177
```

**因为每次留出集只有 22 个词。**

第一次实验报的 `R²(经度) = 0.064`，只是恰好抽到了最低那一次。

### 四重错误叠加的教训

那个 0.06 是四个独立问题共同造成的：

| # | 错误 | 修正 | 影响 |
|---|---|---|---|
| 1 | 用了第 23 层 | 改用第 5 层 | R² 掉约 0.2 |
| 2 | 经度线性编码 | sincos | 约 2 倍差距 |
| 3 | 线性 R² 评价经度 | circular_r2 | 指标本身有偏 |
| 4 | 单次 22 点 | 汇总 176 点 | 抽样噪声 ±0.5 |

**修正后：0.06 → 0.80。**

> **这是"结果不好"和"方法有错"难以区分的典型案例。**
> 只看第一次的数字，"模型不编码经度"是个听起来完全合理的结论 —— 但它是错的。

| 误差是否降到 1,500 km 以下？ | 量化的规模效应 |
| sincos 的改善幅度是否变化？ | 编码缺陷在大模型上是否同样重要 |

#### P1：logit lens，验证"最后一层被挤压"这个机制

现在的解释是**推测**：最后一层为"预测下一个 token"服务，所以世界知识退化。

**logit lens 能把推测变实证**：把每一层的隐层直接乘 `lm_head` 投影到词表，

#### P1：给词表加大洲标签，验证"语义密度加权"假设

第一次分析发现：所有美洲词误差 6,000+ km，所有欧亚非词 < 5,000 km。

假设：**语料密度高的区域表征分辨率高**。

**验证方法**：给每个词加 `continent` 字段，分组统计误差。

#### P2：扩大 A 组到 300+ 词

收窄置信区间，让层间差异更可信。用 `scripts/build_wordlist.py` 可以批量刷坐标。

### 简历/面试怎么说

```
LLM 地理知识探针 · 歧义地名的表征偏移分析（个人项目）
· 用线性探针检验 Qwen2.5-0.5B 是否在内部表征中编码地理坐标，
  以 Haversine 公里误差为主指标，配合置换检验与字符 n-gram 基线排除伪相关。
· 逐层扫描 24 层发现地理知识在第 3–5 层涌现，第 5 层中位误差 2,311 km，
  比默认最后一层低约 30%，比置换检验好 2.6 倍。
· 识别并修正三个会使结论反转的度量缺陷（经度循环编码、圆形 R²、汇总 R²），
  将「经度不可解码」的初步结论（R²=0.06）修正为 0.80。
```

**面试最可能问的一句**：「你怎么保证结论不是方法造成的？」

**答**：

> 我一开始得出"模型不编码经度"（R²=0.06）。后来发现是四重方法错误的叠加：
> 层选错、经度用线性编码、用线性 R² 评价循环量、R² 只用了 22 个样本。
> 全部修正后变成 0.80。
> **这件事教给我的是：在 probing 这类分析里，一个"合理的科学结论"
> 和"方法缺陷"看起来完全一样，必须主动去区分。**
>
> 我的做法是三重对照：置换检验、字符基线、非地名负对照。

## 附录 D：这个实验的「决策清单」

如果你要自己做一个类似的实验，这些是**已经替你踩过的坑**，照着检查：

| # | 决策点 | 天真的做法 | 正确做法 | 本项目实测差距 |
|---|---|---|---|---|
| 1 | 评估指标 | R² / MSE | **Haversine 公里** | R²=0.85 时误差可能 3,000 km |
| 2 | 经度处理 | 直接用度数 | **(sin λ, cos λ)** | 跨日界线误差 127.7° → 0.2° |
| 3 | 经度的 R² | 普通线性 R² | **圆形 R²** | 同一预测：线性 R²=-3.0，圆形 R²=0.5 |
| 4 | R² 的样本量 | 单次划分（22 点） | **汇总所有重复（n=176）** | 单次值跨度可达 1.17 |
| 5 | 取哪一层 | 最后一层 | **逐层扫描找最优** | 第 5 层比第 23 层准 26% |
| 6 | 取哪个位置 | `activations[-1]` | **实体 token 均值** | 避免"任务意图"污染 |
| 7 | 有没有信号 | 看 R² 高不高 | **置换检验** | 纯噪声也能在均值基线下"通过" |
| 8 | 是否只是拼写 | 只看隐层 | **字符 n-gram 基线** | `-stan` 这类后缀会带来伪相关 |
| 9 | 歧义词判定 | 离哪个候选近 | **加可靠性门槛** | 20 个里 12 个是噪声 |
| 10 | 结果可复现性 | 每次重跑模型 | **缓存中间激活（npz）** | 从"几小时"到"几秒" |

**这十条就是这类实验的"检查表"。** 换任何模型、任何属性（不只地理），都适用。
